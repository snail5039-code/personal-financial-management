# 오늘 하루 브리핑

흩어져 있는 일정·메일·할일을 모아서 **2분 안에 읽히는** 우선순위 정리를 준다.
정보를 그냥 나열하는 게 아니라 "지금 뭐부터 해야 하는지"까지 말해주는 게 목적이다.

## 절차

1. **필요한 것만 모은다.** 사용자가 콕 집어 말한 것(예: "메일만")이 있으면 그것만,
   "브리핑"처럼 종합을 요청했으면 아래를 전부 모은다.

   | 무엇 | 도구 |
   | --- | --- |
   | 오늘 일정 | `calendar_search(start_date=오늘, end_date=오늘)` — 두 인자 모두 `YYYY-MM-DD` 필수 |
   | 안 읽은 메일 | `email_search(query="is:unread newer_than:1d", limit=10)` |
   | 미완료 할일 | `todo_search()` — 인자 없이 부르면 미완료만 나온다 |
   | 날씨 | `weather_check(city=...)` |
   | 뉴스 | `news_briefing()` |

2. **우선순위로 정렬한다.** 이 순서가 사용자에게 유용한 순서다.
   1. 시각이 정해진 것 — 오늘 일정 (가장 이른 것부터)
   2. 마감이 오늘이거나 이미 지난 할일
   3. 답장이 필요해 보이는 메일
   4. 나머지 (마감 없는 할일, 참고용 메일)

3. **짧게 보고한다.** 각 항목은 한 줄. 메일은 **보낸 사람 + 제목만** 보여주고 본문은 넣지 않는다
   (사용자가 궁금해하면 그때 `email_read`로 열어본다).
   비어 있는 항목은 조용히 빼지 말고 "오늘 일정 없어요"처럼 명확히 말한다 — 빠뜨린 건지
   없는 건지 사용자가 알 수 없으면 브리핑을 믿을 수 없다.

4. **마지막에 "지금 뭐부터" 한 줄을 붙인다.** 2번 순서에서 가장 위에 있는 것 하나를 고른다.
   이 한 줄이 이 스킬의 핵심이다.

5. **메일이나 일정에서 할 일이 보이면** `todo_registration`으로 등록할지 물어본다.
   묻지 않고 먼저 등록하지는 않는다.

## 주의

- **이건 "지금 보여주는" 브리핑이다.** 트레이 앱이 매일 아침 자동으로 보내는 알림의
  **시각을 바꾸는 것**은 이 스킬이 아니라 `briefing-setup` 스킬이다.
- **Gmail은 읽기 전용이다.** 답장·삭제는 안 된다. 사용자가 답장을 원하면 "커리마로는 읽기만
  되니 Gmail에서 직접 보내야 한다"고 알려준다.
- 날씨를 볼 도시를 모르면 `Seoul`로 조회하고, 보고할 때 "다른 도시면 말해주세요"를 한 줄 덧붙인다.
- 구글 연동이 안 돼 있으면 도구 결과에 안내 문구가 온다. 그걸 그대로 전달하고,
  **나머지 항목(할일·날씨·뉴스)만으로 브리핑을 완성한다.** 하나 막혔다고 전체를 포기하지 않는다.
