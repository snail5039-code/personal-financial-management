# 로컬 문서 의미 기반 검색

파일 이름이 아니라 **내용**으로 문서를 찾는다. 이름을 아는 파일을 찾는 것이면
이 스킬이 아니라 `file_search`를 쓴다.

## 절차

1. **색인이 있는지부터 확인한다.** `local_search`는 색인이 없으면 결과가 하나도 안 나온다.
   결과가 비었을 때 "문서가 없다"고 결론내지 말고, 색인이 아직 없을 가능성을 먼저 의심한다.

2. **색인이 없으면 사용자에게 먼저 알린다.** `index_local_documents`는 문서·바탕화면 폴더를
   전부 훑고 임베딩 API를 호출한다. **시간이 몇 분 걸리고 API 비용도 든다.**
   그러니 바로 실행하지 말고 이렇게 알린 뒤 진행한다:
   "문서 색인이 아직 없어요. 지금 만들면 몇 분 걸리고 API 비용이 조금 들어요. 진행할까요?"

3. **색인이 준비되면 `local_search`로 찾는다.** 검색어는 사용자가 말한 표현 그대로보다
   문서에 실제로 적혀 있을 만한 표현으로 바꿔서 넣는 게 잘 맞는다.

4. **결과를 보고할 때 파일 경로를 반드시 같이 준다.** 사용자가 바로 열어볼 수 있게.
   이어서 열어달라고 하면 `file_open`, 내용을 더 보고 싶다고 하면 `file_read_text`를 쓴다.

## 주의

- 색인은 만든 시점의 문서 상태를 담는다. 최근에 만든 파일이 안 잡히면 색인을 다시 만들어야
  한다는 걸 알려준다.
- 검색 결과가 애매하게 여러 건이면 임의로 하나를 고르지 말고, 후보를 짧게 나열해서
  사용자가 고르게 한다.
